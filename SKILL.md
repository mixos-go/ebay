# eBay Selling / Commerce API Guide

Use this skill to answer exact eBay API structure questions (Selling, Commerce, Buy,
Post-Order) and avoid guessing fields.

## Coverage

- Platform: eBay RESTful public APIs (OAS 3.0). Sell (Inventory, Fulfillment, Account
  v1/v2, Finances, Marketing, Feed, Metadata, Analytics, Negotiation, Recommendation,
  Stores, Compliance, Logistics, Listing), Buy (Browse, Order, Deal, Feed, Offer,
  Marketing, Marketplace Insights), Commerce (Catalog, Charity, Identity, Media,
  Feedback, Message, Notification, Taxonomy, Translation), Developer (Analytics, Key
  Management), and Post-Order (Cancellation, Case, Inquiry, Return).
- 35 category folders under `references/api/` (e.g. `Inventory_API`, `Fulfillment_API`,
  `Account_v1_API`, `Finances_API`, `Marketing_API`, `Browse_API`, `Order_API`,
  `Commerce_Taxonomy_API`, `Post_Order_Return_API`), 385 API docs total.
- Each doc has YAML frontmatter (`title`, `category`, `api_name`, `method`, `path`) plus
  structured sections: `## API Description`, `## Request Parameters`, `## Request Body`,
  and `## Response`.
- Response/request fields are flattened nested trees (parent→child via `.`), with type
  and required flags; array element schema names shown like `array<SomeSchema>`.
- Auth: OAuth 2.0 (authorization code / client credentials / refresh tokens). The OAS
  specifies per-API scopes.

## Workflow

1. Read the request and identify the business capability (inventory, fulfillment,
   account, finance, marketing, order, browse, taxonomy, post-order) and any explicit
   method/path.
2. Map the capability to a category (e.g. inventory → `Inventory_API`, order →
   `Order_API` or `Fulfillment_API`, post-order return → `Post_Order_Return_API`) and
   inspect `references/api/<Category>/<operationName>.md`.
3. Search `references/api/` by operation name, path segment, resource, or keyword when
   unclear.
4. Read the exact method (`GET`/`POST`/`PUT`/`DELETE` in frontmatter/body), the HTTP
   path (e.g. `/sell/inventory/v1/inventory_item/{sku}`), the Request Parameters, the
   Request Body, and the Response schema.
5. Note that some API titles repeat across spec files (e.g. two `Analytics_API`); verify
   the `path` in frontmatter to pick the correct one.
6. If a schema, deprecation, or newer version is not present in the local reference,
   check the official eBay API docs (`https://developer.ebay.com/api-docs`) and state the
   gap/source.
7. Do not invent fields, enum values, required flags, or response shapes absent from the
   selected API's official schema.

## References

- `references/api/<Category>/<operationName>.md` — one clean Markdown doc per eBay operation.
- Category folders map to eBay API products (e.g. `Inventory_API`, `Fulfillment_API`,
  `Account_v1_API`, `Browse_API`, `Post_Order_Return_API`).

## Update & Provenance

- Local reference is a **static snapshot** built from the `hendt/ebay-api` mirror of
  eBay's official OpenAPI 3 contracts (also available directly at
  `https://edp.ebay.com/api-docs/master/.../openapi/3/*_oas3.json`). It is regenerated by
  the toolchain in the `updskills` repo (`tools/spec_to_markdown.py`). To get fresher
  specs, pull the latest eBay OAS contracts and re-run the tool rather than hand-editing.
- For agent use, prefer the official live docs (`https://developer.ebay.com/api-docs`)
  for anything that may have changed since this snapshot (deprecations, new APIs, policy).
